Come si lancia un singolo contratto

Sul server, dentro /home/labeconomia/mdiianni/verimap_projects/smarthorntest. Esempio con short_circuit_and_fail; per un altro contratto basta cambiare il file .sol e la cartella di uscita. Le stesse opzioni dei run del report: timeout 600 s, e per le nostre due strade --maxdepth 100.

Noi, strada SolCMC, come nella run del report: lo script del benchmark analizza tutti gli assert insieme (risultati e test_cases.json nella cartella del secondo argomento, che deve essere un percorso assoluto)

INTERP_OPTS="--maxdepth 100" bash test20Ottobre/_solcmc_uno.sh test20Ottobre/solcmc_maxdepth100/soltg/fail/short_circuit_and_fail/short_circuit_and_fail.sol $PWD/test20Ottobre/singolo/solcmc/short_circuit_and_fail

In alternativa, con il comando del tool, che analizza un assert alla volta in parallelo. Parte in background e scrive i risultati in solcmc/ accanto al file, quindi prima lo copiamo in una cartella sua.

mkdir -p test20Ottobre/singolo/solcmc_tool && cp test20Ottobre/solcmc_maxdepth100/soltg/fail/short_circuit_and_fail/short_circuit_and_fail.sol test20Ottobre/singolo/solcmc_tool/
bash smarthorntest.sh test20Ottobre/singolo/solcmc_tool/short_circuit_and_fail.sol -r solcmc -t 600
tail -1 test20Ottobre/singolo/solcmc_tool/solcmc/run.log; cat test20Ottobre/singolo/solcmc_tool/solcmc/short_circuit_and_fail/short_circuit_and_fail.test_cases.json

Noi, strada yul2chc, con smarthorntest (alias di bash smarthorntest.sh; -f = funzione da testare, -t = timeout; maxdepth 100 viene da smarthorntest.conf). Parte in background e scrive i risultati nella cartella del file, quindi prima lo copiamo in una cartella sua.

mkdir -p test20Ottobre/singolo/smt && cp test20Ottobre/solcmc_maxdepth100/soltg/fail/short_circuit_and_fail/short_circuit_and_fail.sol test20Ottobre/singolo/smt/
smarthorntest test20Ottobre/singolo/smt/short_circuit_and_fail.sol -f g -t 600
tail -3 test20Ottobre/singolo/smt/run.log; cat test20Ottobre/singolo/smt/short_circuit_and_fail.test_cases.json

SolTG, installazione ufficiale dal repository degli autori (bug trovato = un test generato, eseguito con Foundry, fallisce con Panic 0x01)

Il comando è quello del README di SolTG. La cartella ~/soltg_ufficiale/progetto contiene già foundry.toml e forge-std; prima di ogni contratto si puliscono i risultati precedenti e si copia il contratto.

source ~/soltg_ufficiale/env/bin/activate; cd ~/soltg_ufficiale/progetto
rm -rf out test/*; mkdir out; cp ~/verimap_projects/smarthorntest/test20Ottobre/solcmc_maxdepth100/soltg/fail/short_circuit_and_fail/short_circuit_and_fail.sol .
solTg -i short_circuit_and_fail.sol -o out -t 600
cat out/progetto/short_circuit_and_fail/testgen.txt; grep -E "^\[(PASS|FAIL)" out/progetto/short_circuit_and_fail/test_results.txt | sort -u
