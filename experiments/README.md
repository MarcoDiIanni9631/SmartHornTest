# Experiments

Benchmark and results of the evaluation of SmartHornTest in the PhD thesis of
Marco Di Ianni (Chapter 6, Evaluation). Runs of 20-21 October 2026.

## Benchmark

| folder | origin | contracts | with a bug |
|---|---|---|---|
| `soltg/` | regression benchmark of SolTG, files with one contract and assertions | 81 | 30 |
| `smtchecker/` | SMTChecker tests of the Solidity compiler, without mappings, arrays, inline assembly and external calls | 151 | 56 |

Each contract has its own folder `<benchmark>/<category>/<name>/` with:

- `<name>.sol`: the contract as analyzed;
- `<name>_vgood.sol`: the same contract with the `vgood` marker and the
  auxiliary assertion, used to get the positive tests;
- `solcmc.test_cases.json`, `yul2chc.test_cases.json`: the tests found by
  SmartHornTest with the two routes (missing when the route produced no CHCs).

`summary.csv` has one row per contract: the expected answer (`bug` or `safe`,
and how many calls are needed to reach the bug), the outcome of the four tools
and the number of negative and positive tests of each route.

## Outcomes

- `correct`: bug found when there is one, no bug reported when there is none;
- `bug missed`: the contract has a bug reachable with one call and it is not found;
- `bug needs several calls`: the bug needs two or more calls (all tools run one call);
- `false alarm`: a bug is reported on a safe contract;
- `timeout`: no answer within 600 s;
- `not analyzed`: the CHCs (or the bytecode) could not be produced.

The expected answer comes from the SMTChecker comment at the end of each test
file (Warning 6328), from the name of the file (`_fail`), or, for the SolTG
files without a comment, from reading the code.

## Test cases

Each json lists, for every function, its test cases:

- `kind`: `negative` (violates a real assertion) or `positive` (violates only
  the auxiliary assertion, i.e. the real properties hold on that path);
- `failed_assert`: the assertion reached;
- `concrete_values`: one test case found by Z3;
- `constraints_clpq`, `constraints_z3`: the input constraint, i.e. the
  constraint of the path projected onto the Solidity variables, computed with
  CLP(Q) and with Z3; the `_start` versions refer to the state variables at
  the start of the call.

## How to run again

Setup used: depth bound 100, timeout 600 s, one call at a time; solc 0.8.29,
SWI-Prolog 9.3.31, Z3 4.15.3; Mythril 0.24.8, Manticore 0.3.7; two Intel Xeon
Gold 6238R (28 cores, 2.2 GHz), about 200 GB of RAM, Rocky Linux 9.7, four
contracts in parallel.

One contract with SmartHornTest:

    ./smarthorntest.sh experiments/soltg/sanity/simple_if/simple_if_vgood.sol -r solcmc -d 100 -t 600
    ./smarthorntest.sh experiments/soltg/sanity/simple_if/simple_if_vgood.sol -r yul -d 100 -t 600

This folder is generated by `script/build_experiments.py` from the run folders
`test20Ottobre/` (outcomes, Mythril, Manticore) and `test21Ottobre/` (runs
with `vgood`, Foundry).
